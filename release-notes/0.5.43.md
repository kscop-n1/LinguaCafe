# LinguaCafe 0.5.43

This release fixes database backup creation, hardens vocabulary token filtering and cleanup, and includes the reader layout overlap fix from the current regression pass.

## Fixed

- Fixed Admin > Dashboard > Backups returning HTTP 200 for failed database exports. Failed exports now return a structured HTTP 500 response instead of `{ "exitCode": 2 }`.
- Fixed database backup creation in Docker installs where `mysqldump` failed with a TLS/self-signed certificate error. The backup service now runs the dump client with `--ssl=0`, which matches the runtime MySQL setup.
- Reworked backup execution to avoid shell string password exposure. The service now runs the dump executable with structured arguments and passes the database password through `MYSQL_PWD`.
- Backup success now requires exit code `0`, a created SQL file, and a non-empty file size. Empty or partial files from failed exports are removed.
- Added sanitized backend diagnostics for backup failures, including command name, exit code, stderr, output path, and file validation details without exposing DB passwords.
- Updated the backup UI to show success only for the new `success: true` response contract and to treat non-2xx or malformed responses as errors.
- Fixed the reader page layout so the reading pane and vocabulary/details pane behave as separate columns. Reading text now wraps before the divider, and the side toolbar has reserved space instead of overlapping the vocabulary panel.
- Prevented non-word tokens such as `#`, `'s`, `):`, `+1`, `+10d6`, `+2/+4`, and similar punctuation/number/dice/stat fragments from being treated as vocabulary words.
- Filtered existing invalid vocabulary rows out of vocabulary, review, statistics, book, and chapter query paths.

## Added

- Added backup regression tests for:
  - successful dump with a non-empty SQL file;
  - dump exit code `2`;
  - missing dump executable;
  - invalid credentials/connection failure;
  - non-creatable backup destination;
  - empty output with exit code `0`;
  - endpoint success and failure response contracts.
- Added/expanded non-word token tests for punctuation-only tokens, signed numbers, dice notation, slash stat expressions, apostrophe fragments, contractions, hyphenated words, Unicode words, and migrated invalid rows.
- Added the operator-run cleanup command for existing bad vocabulary rows:

```bash
php artisan linguacafe:cleanup-non-word-vocabulary
php artisan linguacafe:cleanup-non-word-vocabulary --apply
```

## Existing DB Cleanup Instructions

The tokenization fix prevents future bad tokens from being created, but existing rows already in the production database must be cleaned manually. The cleanup command is dry-run by default. Run the dry-run first after updating the container:

```bash
cd /home/serhii/docker/linguacafe
docker compose pull
docker compose up -d
docker exec linguacafe-webserver php artisan linguacafe:cleanup-non-word-vocabulary
```

Review the JSON summary before applying. Pay attention to:

- `invalid`
- `would_ignore`
- `known_to_ignore`
- `learning_to_ignore`
- `chapters_repaired`
- `books_recalculated`
- `samples`

To clean one user first:

```bash
docker exec linguacafe-webserver php artisan linguacafe:cleanup-non-word-vocabulary --user-id=1
docker exec linguacafe-webserver php artisan linguacafe:cleanup-non-word-vocabulary --user-id=1 --apply
```

To clean one language first:

```bash
docker exec linguacafe-webserver php artisan linguacafe:cleanup-non-word-vocabulary --language=english
docker exec linguacafe-webserver php artisan linguacafe:cleanup-non-word-vocabulary --language=english --apply
```

To clean all users/languages after reviewing dry-run output:

```bash
docker exec linguacafe-webserver php artisan linguacafe:cleanup-non-word-vocabulary --apply
```

The command does not hard-delete vocabulary rows. With `--apply`, invalid tokens are marked ignored (`stage = 1`), review scheduling is cleared, affected chapter unique-word metadata is repaired, and affected book/chapter word counts are recalculated. The command is intended to be repeatable.

## Backup Notes

The production failure was traced to the dump client returning exit code `2` with a TLS/self-signed certificate error. The runtime container has both `mysqldump` and `mariadb-dump`; `mysqldump --ssl=0` successfully produced a valid SQL dump against the existing MySQL container.

To test backup creation after updating:

```bash
docker exec linguacafe-webserver php artisan app:create-backup
ls -lh /home/serhii/docker/linguacafe/storage/backup
```

The Admin dashboard backup button should now return HTTP 200 only after a valid non-empty SQL file exists. Failed exports return HTTP 500 with a stable `BACKUP_EXPORT_FAILED` payload.
