# LinguaCafe 0.5.42

This release finishes the next migration-regression cleanup pass. It includes additional desktop/tablet UI fixes, hardens Vocabulary book/chapter filtering for old migrated chapter data, and adds a safe cleanup command for existing non-word vocabulary tokens.

## Fixed

- Aligned the sidebar bottom Language control with the Hide and Theme controls in desktop sidebar and mobile drawer layouts.
- Restored a clear active state for User settings tabs.
- Removed unnecessary internal scrollbars from Edit daily Reading/New Words goal dialogs on desktop-sized viewports.
- Reduced Calendar day popover action buttons to compact icon buttons.
- Added spacing between the Reader side toolbar and the vocabulary sidebar so `#vocab-side-box` no longer cuts into toolbar buttons.
- Hardened Vocabulary book and chapter filters when old/migrated chapters have missing, empty, stale, or mismatched `unique_word_ids`.
- Preserved the duplicate-word-text behavior by keeping id-based filtering when `unique_word_ids` are valid.
- Prevented future imports from creating vocabulary rows for non-word tokens such as `#`, `'s`, `):`, `+1`, `+10d6`, `+2/+4`, and `+5d6`.

## Added

- Added `TextBlockService::isVocabularyToken($token, $language)` as the central classifier for future vocabulary token creation.
- Added the dry-run cleanup command:

```bash
php artisan linguacafe:cleanup-non-word-vocabulary
```

- Added command options:

```bash
php artisan linguacafe:cleanup-non-word-vocabulary --user-id=1
php artisan linguacafe:cleanup-non-word-vocabulary --language=english
php artisan linguacafe:cleanup-non-word-vocabulary --apply
php artisan linguacafe:cleanup-non-word-vocabulary --user-id=1 --apply
```

The command is dry-run by default. With `--apply`, it only marks invalid safe stage-2 rows as ignored (`stage = 1`). It does not hard-delete rows. Known words (`stage = 0`) and learning/SRS words (`stage < 0`) are reported but skipped.

## Existing DB Cleanup Instructions

After updating the Docker image, run a dry-run first:

```bash
cd /home/serhii/docker/linguacafe
docker compose pull
docker compose up -d
docker exec linguacafe-webserver php artisan linguacafe:cleanup-non-word-vocabulary
```

Review the printed JSON summary and samples. If the output is expected, apply cleanup:

```bash
docker exec linguacafe-webserver php artisan linguacafe:cleanup-non-word-vocabulary --apply
```

For a safer scoped cleanup, run one user first:

```bash
docker exec linguacafe-webserver php artisan linguacafe:cleanup-non-word-vocabulary --user-id=1
docker exec linguacafe-webserver php artisan linguacafe:cleanup-non-word-vocabulary --user-id=1 --apply
```

Optional language scope:

```bash
docker exec linguacafe-webserver php artisan linguacafe:cleanup-non-word-vocabulary --language=english
docker exec linguacafe-webserver php artisan linguacafe:cleanup-non-word-vocabulary --language=english --apply
```

The command does not automatically clean existing known or SRS/learning rows. Those are intentionally skipped so real user learning data is not changed silently.

## Notes

- Existing production chapter `unique_word_ids` were checked before this release and did not need repair. A small set of stale `unique_phrase_ids` rows was repaired directly from `processed_text` after a production backup.
- Runtime fallback remains in place for older installs where chapter id data is incomplete.
- Non-word cleanup is intentionally an operator-triggered command, not an automatic migration.
