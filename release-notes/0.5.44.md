# LinguaCafe 0.5.44

## Dark theme contrast hardening

This release fixes dark-theme contrast regressions as an application-wide styling issue rather than a Fonts-page-only patch.

- Added shared semantic theme tokens for readable dark-mode text, secondary text, muted text, disabled text, icons, disabled icons, elevated surfaces, input surfaces, borders, dividers, hover, selected and focus states.
- Updated the dark-mode CSS scope for Vuetify 3. The dark class is now applied on the rendered `.v-application`, so dark rules target `#app .v-application.dark` instead of the old `#app.dark` shape.
- Added a shared dark-mode component baseline for page headings, cards, dialogs, menus, tooltips, tables, table footers, action icons, pagination, form fields, tabs, navigation, disabled states, focus states and reader toolbar controls.
- Fixed dark chips and icon buttons that could inherit dark foreground colors on dark surfaces.
- Increased dark border contrast for essential controls and table outlines while keeping softer dividers for row separation.

## Reader layout follow-up

- Kept the reader text pane, vocabulary/details pane and vertical toolbar in separate layout columns.
- Preserved the compact toolbar gap without allowing the toolbar buttons to overlap the reader panel or trigger horizontal overflow.
- Verified the reader layout in dark mode at desktop, tablet and mobile widths.

## Regression guard

- Added `npm run check:dark-theme`.
- `npm run check:css` now also runs the dark-theme contrast guard.
- The guard checks WCAG-style contrast for the dark semantic tokens and verifies that shared dark-mode selectors cover representative components: tables, data-table footer, pagination, tabs, fields, icon buttons, disabled controls, navigation, dialogs, tooltips and reader toolbar buttons.

## Browser verification

Runtime verification was performed against the local dev stack in dark mode.

- Admin Fonts page: visible Fonts heading, active Fonts tab, table headers, table rows, action icons, pagination footer and page-size field were all readable. Sampled computed contrast ratios ranged from 7.32:1 to 14.54:1.
- User Settings page: active settings tab and form field/input text were readable in dark mode. Sampled form-field contrast was 10.78:1.
- Reader page: reader text contrast was 12.59:1; toolbar button/icon contrast was 10.21:1.
- Reader responsive layout: toolbar gap stayed at 8px and horizontal overflow stayed at 0px at 1280px, 1024px and 900px widths. Mobile 390px width also had 0px horizontal overflow.

## Validation

- `npm run check:migration` passed and rebuilt the production bundle successfully.
- `npm run check:dark-theme` passed.
- `npm run check:css` passed the critical check; existing `!important` warnings remain known CSS debt.
- `npm run test:php` passed: 45 tests, 197 assertions.
- `git diff --check` passed.
